## 3. 关键发现(面试可讲)

1. **5B 纯文生不可用**:同工作流去掉 start_image 后输出与文本无关(2 prompt 复现)。TI2V-5B 是 I2V 中心模型——文本决定"怎么动",图像决定"动什么"。"文生视频"需求须由 14B T2V 专家或云端承担。
2. **Errno 22 采样的真实根因是服务启动方式(排错实录)**:l14b/FLF 曾在两种显存模式下均"采样启动即抛 OSError Errno 22"(3 次复现),一度误判为动态显存缺陷;后经对照实验定位——**凡用 PowerShell Start-Process(-RedirectStandardOutput)拉起的服务进程都在采样期崩溃,改用 python subprocess.Popen(追加写日志句柄)启动后两种模式均正常**。Windows 句柄继承差异破坏权重 mmap 是最可能根因(待深挖)。教训:排错时"改了什么"要逐一归因,同机同参数不同启动路径行为不同。16GB 卡跑 14B 实测可用:l14b 4 步 717s/81 帧,FLF 20 步 ≈250s/步,端侧定位"单条叙事镜头",批产需云端/多卡。
3. **步数 A/B**:12 步 149s vs 20 步 203s,20 步纹理更优;视频质量对步数不如图像敏感(动态掩盖细节差异),B-roll 可用 12 步省 26% 机时。
4. **图像先验 > 文本驱动**:真实行走姿态照做首帧的镜头产出最自然的步态;纯静图+文本"迈步"只能得到重心转移级的小动作。选首帧 = 选动作上限。
5. **幻觉手势是 5B 最大翻车点**(审片记录 4 例):掏纸巾打喷嚏 / 凭空皮包 / 抬手鬼影 / 摆臂糊块;对策 = prompt 显式写死"双臂下垂/无手势/无物件"+ 裁片避开手部 + 五维审片拦截。良性幻觉(托脸、编织包)反而加分,按个案放行。
6. **节点版本坑**:新版 ComfyUI 的 WanFirstLastFrameToVideo 把 clip_vision 拆为 start/end 两个输入(旧签名 clip_vision_output 直接 TypeError)——API 化工作流必须对安装版本核对节点签名。

## 4. 工程沉淀

- `v13_video.py`:三路线参数化(shot/ab 命令),首帧缓存裁片(bias 人脸对齐),胶片条内嵌工作流,_runs.jsonl 结构化记录
- `v13_edit.py`:probe/inspect/strip/gif/conform/fade/reel 全链(纯 ffmpeg,conform 强制 24fps 防混帧率)
- `v13_pack.py`:胶片条 plate + 精选视频包 + reel 一键打包
- 审片流程:inspect 抽首/中/尾帧 → 手部区域 2× 放大 → 五维评分 → 多 seed 重掷(上限 4)→ 止损降级
- 看门狗沿用 comfy_api.run_watchdog(防 RAM 页交换);14B 路线改直连 queue 避免重启丢 DynamicVRAM 配置

## 5. 与图片管线的关系

- 首帧全部取自 upscaled_v10 的 V11 终选成片(2600×3466),**视频与静图共用同一身份锚**,换装/场景/姿态三案例的视频化是图片管线的自然延伸
- FLF 首尾帧 = 换装案例的 BEFORE(真实输入)/AFTER(管线成片)直接作首尾帧——"一条视频内完成换装"是电商视频化的强卖点
- PDF 文案沿用"如实说明"范式:幻觉手势、动作幅度边界、T2V 判负全部如实入册
